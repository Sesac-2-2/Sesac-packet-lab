Packet.AI 프로젝트 안내

패킷 증거를 바탕으로 네트워크 장애를 진단하고, 복구 후 다시 검증하는 4인 협업 실습 프로젝트입니다.

프로젝트는 무엇을 하나요?

Packet.AI는 사내 네트워크에서 발생하는 접속 장애를 정상 상태와 비교해 분석하는 프로젝트입니다. 단순히 증상만 보고 원인을 추측하지 않고, ARP·ICMP·DNS·TCP·HTTP 패킷에서 관찰한 사실을 근거로 원인 후보를 좁힙니다. AI는 진단을 보조하고, 마지막에는 SRE가 실제 복구와 재검증을 수행합니다.

1. Network Architect

정상 네트워크의 주소, VLAN, 장비 연결 기준을 설계합니다.

2. Packet Analyst

정상·장애 패킷을 캡처하고 관찰값을 JSON으로 정리합니다.

3. AI Engineer

증거를 바탕으로 원인 후보와 추가 확인 방법을 제안합니다.

4. Network SRE

장애를 재현·복구하고 복구 결과를 보고합니다.

왜 이런 방식으로 하나요?

"웹사이트에 접속할 수 없다"는 하나의 증상에도 DNS 설정 오류, 기본 게이트웨이 오류, VLAN 연결 오류, 서버 서비스 중지처럼 여러 원인이 있을 수 있습니다. 증상만으로 한 원인을 단정하면 잘못된 조치로 시간을 잃을 수 있습니다.

  • 증거 기반 판단: 패킷에 실제로 무엇이 보였는지부터 확인합니다.
  • 정상 기준선 비교: 장애 패킷만 보지 않고, 같은 조건의 정상 패킷과 첫 차이를 찾습니다.
  • 안전한 AI 활용: AI는 확정 대신 근거·후보·추가 점검 사항을 제시합니다.
  • 복구 검증: 설정 변경 뒤 동일한 테스트를 반복해 서비스 흐름이 회복됐는지 확인합니다.

역할별 작업과 산출물

역할폴더주요 작업다음 단계에 전달하는 것
1. Network Architect01_network_design/IP, VLAN, 서버, 스위치·L3 인터페이스 구조와 Packet Tracer 설정을 작성합니다.network_spec.md, 장비 설정 파일
2. Packet Analyst02_packet_capture/정상·장애 캡처, Wireshark 비교, 패킷 통계와 관찰 사실의 구조화를 담당합니다..pcapng, packet_analysis.md, packet_summary.json
3. AI Engineer03_packet_ai/패킷 요약에서 장애 후보, 근거, 다음 확인 방법을 생성하는 분석기를 구현합니다.diagnosis.json
4. Network SRE04_incident_response/장애 적용·복구, 설정 검증, Incident Report와 Dashboard 작성을 담당합니다.복구 기록, Incident Report, Dashboard 데이터

실제 분석 흐름

  1. 정상 Baseline 확보 — 정상 상태에서 PC가 서버와 통신할 때의 ARP, DNS, TCP 흐름을 캡처합니다.
  2. Blind Fault 적용 — 분석자는 원인을 모르는 상태에서 익명 사례 번호와 증상만 받습니다.
  3. 동일 조건으로 캡처 — 정상 때와 같은 테스트, 캡처 위치, 필터, 캐시 조건으로 장애 패킷을 수집합니다.
  4. JSON 요약 생성 — 패킷 수, DNS 응답, TCP SYN/SYN-ACK/RST, 관찰 한계 등을 구조화합니다.
  5. AI 진단 — AI가 근거 기반 후보와 추가로 확인할 장비·패킷을 제안합니다.
  6. 정답 공개·복구·재검증 — SRE가 원인을 확인해 복구하고 동일 테스트로 결과를 검증합니다.

중요: 값이 0이면 해당 항목을 관찰했지만 패킷이 없었다는 뜻입니다. null은 수집하지 못했거나 판단할 수 없다는 뜻입니다. 이 둘을 구분해야 AI가 "확인되지 않은 실패"를 장애로 오해하지 않습니다.

핵심 구성 요소

패킷 분석과 교육용 실습

02_packet_capture/에는 정상 Baseline 캡처, pcapng에서 JSON을 만드는 summarize_pcap.py, Linux 재현 실습망(lab_env/), ARP·DNS·TCP·VLAN을 학습하는 웹앱(learning_lab/)이 있습니다. 교육용 예제는 실제 장애 증거와 분리해 관리합니다.

AI 진단 보조

03_packet_ai/analyzer.py는 JSON을 읽고 규칙 기반 또는 선택적 AI 기반으로 진단합니다. 결과에는 관찰 근거, 원인 후보, 확신 수준, 추가 확인 항목이 담기며, AI가 패킷에 없는 사실을 단정하지 않도록 설계했습니다.

장애 대응과 보고

04_incident_response/fault.sh는 실습망 장애의 적용·공개·복구·검증을 지원합니다. dashboard.html은 패킷 요약, AI 진단, 복구 기록을 한 화면에서 확인하는 Incident Report 역할을 겸합니다.

팀원이 시작하는 추천 순서

  1. 01_network_design/network_spec.md로 네트워크 기준을 이해합니다.
  2. 02_packet_capture/learning_lab/index.html을 열어 패킷 흐름과 장애 사례를 학습합니다.
  3. WSL2 재현 실습망에서 정상 Baseline을 캡처합니다.
  4. 익명 장애를 적용하고 캡처·JSON 요약·AI 분석을 차례로 수행합니다.
  5. 원인을 공개한 뒤 복구하고, 같은 테스트로 재검증합니다.
  6. 복구 기록과 Dashboard로 증거와 결과를 공유합니다.
