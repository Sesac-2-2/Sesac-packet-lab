Packet.AI — 협업 프로젝트 미션

Packet Tracer + Wireshark + AI Agent + Incident Response
TEAM PROJECT 4인 1조 Collaborative Project

미션: 장애가 발생한 사내 네트워크를 설계·분석·진단·복구하라

단순히 ping을 성공시키는 것이 아니라, 장애 원인을 패킷 증거로 설명하고 AI가 진단하도록 구현하는 것이 최종 목표다.

회사 상황

가상의 스타트업 PacketLab은 개발팀과 운영팀이 서로 다른 VLAN을 사용한다. 어느 날 일부 PC는 서버에 접속되지 않고, 일부는 DNS 조회가 정상적으로 되지 않으며, 특정 VLAN에서는 외부 통신이 되지 않는 문제가 발생했다.

진행 원칙
설정 화면만 보고 원인을 추측하기보다, Packet Tracer Simulation이나 Wireshark에서 보이는 현상을 먼저 살펴본다.
“어떤 패킷이 보였는지 → 그 현상이 무엇을 뜻하는지 → 어떤 원인을 생각할 수 있는지” 순서로 설명하면 프로젝트의 흐름이 훨씬 자연스럽다.

조원 간 공유 Pipeline

프로젝트 수행 단계

1

정상 네트워크 설계

먼저 장애 없는 기준 상태(Baseline)를 완성한다.

2

Baseline 패킷 확보

정상일 때 ARP, ICMP, DNS, TCP가 어떻게 보이는지 기록한다.

권장 Wireshark Filter

arp
icmp
dns
tcp
tcp.flags.syn == 1
http
장애 패킷만 보면 무엇이 달라졌는지 판단하기 어렵다. 가능하면 정상 상태의 패킷을 먼저 확보해 비교 기준으로 사용한다.
3

원인을 숨긴 장애 상황 재현

4번 담당자가 네트워크 설정의 일부를 변경해 장애 상황을 만든다. 다른 조원들은 원인을 바로 전달받기보다, 증상과 패킷을 관찰하면서 가능한 원인을 하나씩 좁혀본다. 실제 운영 환경에서 장애 원인을 처음부터 알고 시작하는 경우가 드물다는 점을 경험해보는 단계다.

장애 A
Default Gateway 오류
장애 B
잘못된 VLAN 할당
장애 C
Trunk에서 특정 VLAN 누락
장애 D
DNS Server 설정 오류
장애 E
Subnet Mask 오류
장애 F
Server TCP Port 서비스 중단
4

패킷 증거로 원인 후보 만들기

Packet Tracer 설정 화면만 보고 맞히지 않는다. 증거를 먼저 수집한다.

증상패킷에서 볼 것가능한 원인 후보
Gateway 통신 이상ARP Request 반복 / Reply 없음Gateway IP 오류, VLAN 오류, SVI Down
같은 VLAN 일부 구간 통신 이상ARP/MAC 학습 차이Port VLAN 오류, 링크 문제
IP ping은 되지만 도메인 조회가 되지 않음DNS Query/ResponseDNS 설정/서버 문제
서버 IP ping은 되지만 웹 연결이 되지 않음TCP SYN/SYN-ACK서비스 Port, Firewall, Server App 문제
5

Packet.AI 입력 데이터 생성

PCAP 전체를 무작정 LLM에 던지지 않고, 핵심 특징을 구조화해 넘긴다.

{
  "case_id": "FAULT-03",
  "source_ip": "192.168.10.10",
  "destination_ip": "192.168.20.20",
  "arp_request_count": 8,
  "arp_reply_count": 0,
  "icmp_request_count": 0,
  "icmp_reply_count": 0,
  "dns_query_count": 0,
  "tcp_syn_count": 0,
  "notes": "Gateway ARP 반복"
}
6

AI Agent 진단

AI는 하나의 답만 말하는 것이 아니라 근거 → 가설 → 추가 확인 → 결론 순서로 판단한다.

Observe
  ↓
Evidence Summary
  ↓
Hypothesis 1 / 2 / 3
  ↓
추가 확인 명령 제안
  ↓
Evidence 재확인
  ↓
Root Cause
  ↓
Recovery Action
7

복구 및 검증

설정을 수정한 뒤 동일 테스트를 다시 실행하여 패킷 차이를 비교한다.

AI Agent 구성 예시

Packet Analyzer Agent

질문: 패킷에서 무슨 현상이 보이는가?

  • ARP 반복?
  • ICMP Reply 없음?
  • DNS Response 없음?
  • TCP SYN 반복?

Root Cause Agent

질문: 이 증거로 가능한 원인은 무엇인가?

  • L2 문제?
  • L3 문제?
  • DNS 문제?
  • Application 문제?

Recovery Agent

질문: 무엇을 확인하고 어떻게 고칠 것인가?

  • 확인 명령
  • 수정 제안
  • 복구 후 검증 방법
조금 더 발전시키는 방법: AI가 처음부터 하나의 원인으로 단정하기보다, 몇 가지 가능성을 제시하고 “추가로 무엇을 확인하면 좋을지” 질문한 뒤 새로운 증거를 받아 범위를 좁히게 할 수 있다.

진행하면서 피하면 좋은 형태

  • ping 성공 여부만 확인하고 패킷 흐름은 살펴보지 않는 경우
